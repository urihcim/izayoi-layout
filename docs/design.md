# 十六夜配列 設計仕様

[要件](requirements.md) をどう実現するか。配列の実装方式と、配列を生成・評価するツールの設計。
状態の表し方（決定 / 仮 / 未定）は要件と同じ。

最終更新: 2026-11-10

## 1. 全体の構成

```
layout/izayoi.toml ──(izayoi ahk)──> dist/izayoi.ahk      実装
        ▲         └──(izayoi chart)──> README.md の配列表
        │ 採用した候補を反映
candidates/*.toml <──(izayoi optimize)── config/optimize.toml
        │                                        corpus/kana.txt
        └──(izayoi eval)──> 指標・打鍵数の目標    config/cost.toml
                                                  config/targets.toml
```

| 項目 | 内容 | 状態 |
| --- | --- | --- |
| 配列の定義 | `layout/izayoi.toml` を唯一の定義元にする | 決定 |
| 候補 | 生成・検討中の配列案は `candidates/` に置く。採用したものを `layout/izayoi.toml` に反映する | 決定 |
| キーの位置 | US 配列。各面 33 キー（上段 `q`〜`]` 12、中段 `a`〜`'` 11、下段 `z`〜`/` 10） | 仮 |
| ツール | Python（uv で管理）。コマンドは `izayoi` | 決定 |

## 2. 実装

### 2.1 共通の方針

| 項目 | 内容 | 状態 |
| --- | --- | --- |
| 生成 | 環境ごとの実装は、すべて配列定義から生成する | 決定 |
| OS 固有の処理 | 各環境向けのジェネレーター（`src/izayoi/<環境>.py`）に閉じ込め、配列定義や評価には持ち込まない | 決定 |
| 単独打鍵の表し方 | 配列定義では `[prefix] solo = { d = "。", k = "、" }` と書き、打鍵列は「シフトキー＋確定系のキー」とする（評価では確定系のキーをスペース 1 打として数える） | 決定 |

### 2.2 Windows: AutoHotkey

| 項目 | 内容 | 状態 |
| --- | --- | --- |
| 実装方式 | AutoHotkey v2 のホットストリング（`*?CX`）。各キーのホットストリングから、生成した関数 `izayoiKey()` を呼ぶ | 決定 |
| 使い方 | 生成物は単独で実行できるスクリプトにする。ほかのスクリプトを前提にしない。ほかのスクリプトから `#Include` して使うこともできる | 決定 |
| 有効にする条件 | `#HotIf izayoiCondition()`。グローバル変数 `izayoiCondition` に入れた関数を呼ぶ。既定は `izayoiKanaInput`（フォーカスのあるウィンドウの IME が ON で、かな入力か。`WM_IME_CONTROL` の `IMC_GETOPENSTATUS` と、`IMC_GETCONVERSIONMODE` の `IME_CMODE_NATIVE` を見る。Shift 単独などで英数に切り替えると無効になり、キーを IME にそのまま渡す）。`#Include` する側が関数を代入すれば差し替えられる。`#Include` した側の `#HotIf` は生成物の `#HotIf` で上書きされるので、外から囲んでも条件を変えられない | 決定 |
| 生成 | 配列定義から AHK スクリプトを生成する。生成物は手で編集しない | 決定 |
| 生成物の管理 | `dist/izayoi.ahk` を git で管理する。配列定義やジェネレーターを変えたら生成し直してコミットする（テストで食い違いを検出する） | 決定 |
| 文字コード・改行 | UTF-8（BOM 付き）、CRLF | 決定 |
| かなの送り方 | かなを `SendEvent` で直接送る（`{Text}` で記号も文字どおりに送る）。新しい Microsoft IME は、確定後に Ctrl+A → BackSpace で中身を全部消すなどすると、Unicode で送った文字を変換中の文字列に入れず確定状態で入れるようになる（IME の OFF→ON では戻らず、別のウィンドウに切り替えると戻る）。以前のバージョンの Microsoft IME では起きないので、そちらを使う前提とする。ローマ字のキーで送る案は、ローマ字で打てない記号が残るので採らない | 決定 |
| 前置シフト・後置シフトの判定 | 複数キーのホットストリングにはしない。ホットストリングの判定は打ったキーの並びの末尾で一致を見るので、前置シフトの 2 打目を次の前置シフトの 1 打目と読み違える（K→D→J が D→J に一致する）。代わりに `izayoiKey()` が「待っている前置シフトのキー」と「直前に出した文字」を覚えておき、配列定義と同じく出力した文字で後置シフトの規則を引く | 決定 |
| 状態を捨てる条件 | 直前に押したキー（`A_PriorKey`）が状態を残したキーでなければ捨てる。BackSpace・カーソル移動・配列外のキー・マウスのクリックなどを挟むと、前置シフトも後置シフトも効かない | 仮 |
| 後置シフトでの置き換え | 直前の文字の文字数だけ BackSpace を送って、置き換え後の文字を送る。置き換えた文字にはさらに後置シフトをかけない | 決定 |
| 単独打鍵 | 前置シフトのキーを打った時点で句読点を出しておき、次のキーで前置シフトになれば BackSpace で消す。直後の Space や Enter はそのまま IME に渡す（句読点の後の Space で変換が始まる） | 仮 |
| 未割り当ての組み合わせ | 前置シフトの後の `_` のキーは何も出さない | 仮 |
| 配列の外のトリガー | 今は使っていない（2026-11-04 に丸数字の規則をやめた）。後置シフトのトリガーにした数字キー（○＋1→①）は、ホットストリングでなく `#HotIf izayoiCondition() and izayoiRawReady("1")` の下のホットキーにする。直前の文字にその数字の規則があり、前置シフトを待っていないときだけ取り、ほかのときは数字キーをそのまま IME に渡す。配列定義では `[[postfix]]` の `trigger` に数字を書く（`layout.RAW_TRIGGERS`）。評価では、数字キーを含む打鍵は数えない（コーパスでは入力できない文字として扱う） | 仮 |
| 動作確認 | 作者の Windows 環境（以前のバージョンの Microsoft IME）で使っている | 仮 |

### 2.3 Linux（候補）

実装方式は未定。候補は次のとおり。

| 方式 | 長所 | 短所・要調査 |
| --- | --- | --- |
| Mozc（fcitx5-mozc / ibus-mozc）のローマ字テーブル | IME の機能なので、IME が ON のときだけ効く。前置シフトも後置シフトも「キーの並び → かな」の規則として書ける。Google 日本語入力と同じ形式なので、Windows・macOS でも使える見込み | 後ろに長い規則が続きうる並びは、次のキーを打つまで確定せず、英字のまま表示される。後置シフトの規則の対象になる文字でそうなる（外来語音・約物だけなら頻度は低い見込み）。避ける書き方があるかは要調査 |
| キーリマッパー（kanata など） | Linux・Windows・macOS で共通に使える | IME の状態を知る仕組みがなく、IME が ON のときだけ有効にするのが難しい |
| fcitx5 / IBus の独自エンジン | 振る舞いを自由に作れる | 作る量が多く、保守の負担も大きい |

第一候補は Mozc のローマ字テーブル。採用する場合は、Windows でも Google 日本語入力で同じテーブルを使えるので、
AHK と並べて比べる（要件「OS 間の一貫性」）。

## 3. 評価

### 3.1 コーパス

| 項目 | 内容 | 状態 |
| --- | --- | --- |
| 基本のコーパス | 青空文庫の作品から、新字新仮名・著作権切れのものを 150 件無作為に選ぶ（かなで約 400 万字） | 仮 |
| 読みの変換 | fugashi + unidic-lite で、表記どおりのかなにする（例: 助詞「は」→「は」、東京→とうきょう） | 決定 |
| 残す記号 | 、 。 ー 「 」 ？ ！ | 仮 |
| 区切りにする文字 | 英数字、上記以外の記号、改行など。区切りをまたぐ 2 打鍵は数えない | 仮 |
| 自分の文章 | `corpus/raw/<名前>/*.txt` に置くと加えられる | 決定 |
| n-gram 表 | ロゴス配列の作者が公開しているモーラ単位の n-gram 表（note・Wikipedia・青空文庫の約 1,000 万字、[出典](https://sizu.me/ditto/posts/2n3nhwene9ae)）。`corpus-fetch-ngram` で `corpus/ngram/logos/` に取得し、`eval` / `optimize` の `--corpus` にディレクトリを渡すと使う。利用条件が明記されていないので、git には入れない | 仮 |

**課題**: 青空文庫は小説が中心なので、カタカナ語が少なく、会話の「」が多い。
普段書く文章を加えて偏りを補う（要件 4「評価に使う文章」）。
n-gram 表は現代文が中心で偏りを補えるが、「」？！ を含まない。

n-gram 表の扱い:

| 項目 | 内容 | 状態 |
| --- | --- | --- |
| 使う表 | 1-gram と 2-gram。指標はすべて 1 打鍵と 2 打鍵の組で決まり、2 打鍵の組は直前の 1 モーラより前に依存しないため。3-gram は 3 打鍵以上の指標を入れるときに使う | 決定 |
| 分割 | モーラごとに、文章と同じ最長一致で分ける。モーラをまたぐ打鍵単位（複数のかなを 1 キーに置いた単語など）は認識しない | 決定 |
| ローマ字の比較 | ん・っ のつづりは直後のモーラで決める。っ へ入る 2 打鍵は、っ のつづりの出現比で按分する | 決定 |

### 3.2 打鍵の数え方

| 項目 | 内容 | 状態 |
| --- | --- | --- |
| 分割 | コーパスを、キーに置いた文字と後置シフトで出す文字に、最長一致で分ける | 決定 |
| 後置シフト | 「直前の文字＋トリガー」の 2 打鍵として数える | 決定 |
| 単独打鍵 | 「シフトキー＋スペース」の 2 打鍵として数える。スペースは親指で打ち、どちらの手とも組み合わせの負担は生じないとする | 仮 |
| 前置シフト | 「シフトキー＋文字のキー」の 2 打鍵として数える | 決定 |
| 後置シフトの衝突 | 規則と同じ並びが文字どおりに現れた回数を数える | 決定 |
| 拗音のシフト省略 | シフト面の い段の文字を拗音キーの直前でシフトなしに打つ打鍵は、別の打鍵単位（例: `に*`）として、そのキー 1 打で数える。後置シフトのシフト省略（`postfix = true`）も同じで、規則の直前の文字の打鍵単位（例: `ふ*`）を 1 打で数える。最適化では、省略できるかが配置で変わるので、規則ごとの打鍵単位（例: `ふ*ゃ`）にし、省略できない配置ではシフト付きの 2 打で数える | 決定 |
| 打鍵数の目標 | `config/targets.toml` の各文字列を、単打・前置シフト・単独打鍵・後置シフトを組み合わせた最少の打鍵数で数え、目標と比べる（`eval --targets`）。コーパスでの頻度は関係しない | 決定 |
| 後置シフトの数え方の制限 | 同じ文字列を普通に打つ方法と後置シフトの両方で打てるときは、コーパスの分割では常に後置シフトとして数える。また、後置シフトで出した文字に続けて別の後置シフトをかける使い方は数えない | 仮 |

### 3.3 コストモデル

`config/cost.toml` で調整する。値は相対的なもので、配列どうしの比較にだけ使う。

| 項目 | 内容 | 状態 |
| --- | --- | --- |
| キーごとの負担 | 人差し指・中指のホーム段を 1.0 とし、文字のキーでは最大 2.8（左小指の `Q` `Z`）。`[` `]` は 2.5 / 3.0。右人差し指の `Y` は 2.0 で、ロウスタッガードでは `J` から 1.25 キー左上に伸ばすことになり、右人差し指で最も遠い（`H` は 1 キー、`N` は 0.5 キー）。1.8 では く（2.1%）が `Y` に来て、伸ばしがつらかった（draft-s16） | 仮 |
| 右小指の負担 | `;` 2.0、`'` 2.6、`P` 2.6、`/` 2.6。小指に置く文字は制約で決めず、この重みで決める。以前は `;` 1.6、`'` 2.2、`P` 2.2 に、頻度の高い文字（青空文庫で 2% 以上）を小指に置かない制約を併用していた。その重みのまま制約を外すと、な が `A`、は が `;`、く が `'` に来て左小指が 4.6% に増えた。小指を 0.4 重くした今の値では、制約なしに探しても制約があったときとほぼ同じ配置になる。さらに以前の `;` 1.3、`'` 1.8、`P` 2.0 では、`;` が `G` `H`（1.4）より軽く、頻出文字（ん く き つ）が集まって右小指の打鍵が 8〜10% になった（draft-s1） | 仮 |
| 左小指の負担 | `Q` 2.8、`A` 2.2、`Z` 2.8 で、同じ段の右小指（`P` 2.6、`;` 2.0、`/` 2.6）より 0.1 重くし（右利きの 0.1 と合わせて 0.2）、左小指の打鍵を右小指より少なくする。右小指は 4 キー（`P` `;` `'` `/`）に加えて 「 」 の `[` `]` も受け持つので、左小指（3 キー）より多くてよい。以前、の（4.2%）が左小指に来ると、青空文庫では左小指 < 右小指でも n-gram 表では逆転した（draft-s4 で 4.8% 対 4.2%）。n-gram 表には 「 」 がなく右小指が約 0.7 ポイント少なく出るのと、ー が青空文庫では 0.11%、n-gram 表では 1.05% と差が大きいため | 仮 |
| 1 打鍵ごとの負担 | すべてのキーの負担に 0.5 を足す（`stroke`）。0 では前置シフト（`D`/`K`＋ホーム段 = 2.0）が通常面の `P`（2.0）と同じ扱いになり、打鍵/かなが 1.35 に増える。0.5 以上では 1.32 前後で頭打ちになる | 仮 |
| 左右差（利き手） | 右利きに合わせ、左手のキーを一律 0.1 重くする。ロウスタッガードで左手の濁音（同手シフト）が打ちにくかったため（draft-s13 の ど `D`→`R`、ぐ `D`→`X`） | 仮 |
| 段のずれ（ロウスタッガード） | 上段は中段より 1/4 キー左、下段は 1/2 キー右にずれる（`[stagger] offset`）。同じ手の別の指で段をまたぐとき、ずれで横の間隔が 1 キーに満たなくなる分 × 2.0（`cramp`）を 2 打鍵の負担に足す。`D`→`X` は 0.5 キー、`D`→`R` は 0.25 キー近づき窮屈になる。`D`→`W` は離れるので足さない | 仮 |
| 2 打鍵の組み合わせ | 同じ指の連続、同じキーの連打、上段と下段をまたぐ打鍵を不利に、内向きのロールを有利にする | 仮 |
| 3 打鍵以上の連なり | 評価していない | 未定 |
| 比較の基準 | QWERTY のローマ字入力（IME で通る最短のつづり）。`[` `]` `?` `!` は Shift の同時押しを負担に含める | 決定 |

### 3.4 指標

| 指標 | 意味 |
| --- | --- |
| 打鍵/かな | かな 1 文字あたりの打鍵数 |
| コスト/かな | キーの負担と 2 打鍵の組み合わせの負担の合計を、かな 1 文字あたりにしたもの（最適化の目的関数） |
| 前置シフト率% | かな 1 文字あたりの前置シフトキーの打鍵数 |
| 同指連続% | 同じ指で別のキーを続けて打つ割合 |
| 段越え% | 同じ手で上段と下段を続けて打つ割合 |
| 内ロール% / 外ロール% | 同じ手・同じ段で、隣の指へ内向き / 外向きに続けて打つ割合 |
| 後置衝突% | 後置シフトの規則と衝突する並びの出現率 |

## 4. 配列の生成

| 項目 | 内容 | 状態 |
| --- | --- | --- |
| 方式 | 焼きなまし法。後置シフトの規則と置く文字は固定し、どのキーに置くかだけを探す | 決定 |
| 探索の量 | 60 万回 × 初期配置を変えて 4 回（クラウドで約 4 分）。20 万回では seed ごとのコストの差が大きく、8 つの seed の最小も 60 万回より高かった | 仮 |
| 結果の扱い | 似たコストの解が複数ある。出てきた配置は「案」として扱い、制約で詰めていく | 決定 |

### 4.1 調整の仕組み

`config/optimize.toml` で調整する。詳しい書式は同ファイルのコメントを参照。

| 調整したいこと | 方法 |
| --- | --- |
| 置く文字を変える | `optimize.units` |
| 後置シフトの規則を変える | `[[postfix]]` の `trigger` と `[postfix.rules]` |
| 特定の文字を特定のキーに固定する | `[constraints.pinned]`（例: `"、" = "base @,"`） |
| 場所を特定の文字専用にする | `[[constraints.exclusive]]` の `area` と `units` |
| 2 つの文字の位置をそろえる | `[constraints.aligned]`（例: `"が" = "か"`） |
| 置ける場所を制限する | `[[constraints.area]]` の `in` / `not_in`（例: 句読点は右手の小指以外 `"right !pinky"`） |
| キーを空けておく | `constraints.reserved` |
| 気に入った案を土台に一部だけ動かす | `optimize --init <配列> --free '<動かす文字>'`。制約に違反している文字は自動で動く |
| 手で直した配列を確かめる | `eval <配列> --config <設定>` で、指標と制約違反を確認する |
| 指の負担の感じ方を変える | `config/cost.toml` |

### 4.2 要件の原則の表し方

要件の「原則」は、プログラムに固定せず `config/optimize.toml` の制約として書く。
例外を作りたいときは、制約を書き換えればよい。

| 原則 | 制約 |
| --- | --- |
| 同手シフトは濁音・半濁音専用 | `[[constraints.exclusive]]`（`area = ["same"]`） |
| 濁音・半濁音は対応する文字と同じキーに置く | `[constraints.aligned]`（例: `"が" = "か"`）。対応する文字と一緒に動かす |
| 句読点は `D`/`K` の単独打鍵 | `[[constraints.exclusive]]`（`area = ["solo"]`）と `[[constraints.area]]`（`in = ["solo"]`） |
| っ ん ー ゃ ゅ ょ は通常面 | `[[constraints.area]]`（`in = ["base"]`）。青空文庫では ー の頻度が 0.11% と低く出るため、評価に任せずに制約で決める。この制約の有無でコストは変わらない（1.75 のまま）ことを確認済み |
| 濁音・半濁音は同手シフトに置く | `[[constraints.area]]`（`in = ["same"]`） |
| `'` には濁音・半濁音と組にならない文字 | `[[constraints.area]]`（`not_in = ["base @'", "d @'"]`）。清音など組になる文字を、通常面と D 面（異手シフト）の `'` に置かない。K＋`'` は同手シフトなので、濁音のほかは置かれず空く |
| 拗音のシフト省略（要件 2.2） | `[shift_omission]` の `units` と `triggers`。配列定義にも同じ表を書き、シフト省略の後置シフトは配置から自動で作る（同じキーの通常面の文字＋拗音キー → い段＋拗音）。最適化では、省略できない配置（同じキーの通常面が空、または い段）と、シフト省略で無効になる後置シフトの規則（同じキーの通常面が い う え など規則の直前の文字）に、1 件あたり 1.0 のペナルティを付けて避ける。`postfix = true` では、拗音キーの後置シフトの規則も、直前の文字がシフト面にあれば同じキーの通常面の文字＋拗音キーで打てるように、規則を配置から自動で作る。同じキーの通常面の文字にその拗音キーの規則がある、または い段 のときは作らない（シフトを付けた 3 打のまま。`eval --detail` に一覧を出す）。同じキーの通常面を取り合うときは、い段、次に `config/optimize.toml` で先に書いた規則を優先する。直前の文字が記号（ひらがな以外）の規則は作らない。省略できない配置にペナルティは付けず、打鍵数の差だけをコストに入れる。`preferred` に書いた文字（ふぁ ふぃ ふぇ ふぉ ふゅ）を出す規則は、シフトを省略できない配置に 1 件あたり 1.0 のペナルティを付け、必ず 2 打で打てるようにする。`overridable` に書いた文字を出す規則は、通常面の文字の規則でも省略を妨げず、省略で作った規則に置き換わる（ペナルティも付けない。draft-s7a / s8 で ゐ に使ったが、ゐ が打てなくなるので今は使わない） |
| 打鍵数の目標（要件 2.4） | 外来音・古語の後置シフトの規則（`[[postfix]]`）。記号の規則は配置が決まってから配列定義に書く。外来音の規則の直前の文字は通常面に固定しない。目標を満たすかは `eval --targets` で確かめる |
| `[` `]` は使わない | `[constraints] reserved = ["@[]"]`。「 」 は IME に渡す `[` `]` で打つので、置く文字（`units`）に入れない。`eval` では 「 」 を後置シフト（っ＋ゃ／ょ）の 2 打で数えるので、コスト/かなが 0.016 ほど高く出る（2026-11-04 の見直しで 2.6048 → 2.6213。「 」 を `[` `]` に置いて数えると 2.6049） |
| 句読点の置き場所の確認 | 、 。 は単独打鍵のほかに D＋`C` / K＋`'` にもある。`eval --config` の制約の確認では、単独打鍵の場所で確かめる |

場所のセレクター `same` は同手シフト（D＋左手、K＋右手）、`cross` は異手シフト（D＋右手、K＋左手）、
`solo` は `D`/`K` の単独打鍵を表す。

`aligned` の対象になった文字（濁音など）は単独では動かさず、対応する文字（清音など）を動かすときに一緒に動かす。
そのため、清音どうしが同じキーに重なる配置（例: 通常面の `J` に か、D 面の `J` に さ）は取れない（が と ざ が同じ位置になるため）。
